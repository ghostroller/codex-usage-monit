## 对建议的限定

没有找到推翻 F1–F4 核心结论的证据。以下边界决定了实际修复范围：

- F2 按最小修复恢复标记与重建调度；单次账户刷新期间仍可能短暂显示带降级标记的 token-share 结果。未改公开报告结构以持久化原始权重。
- R2 的文件锁保护并发写入期间的可见性，不能证明崩溃一致性；但同 payload 重试确实幂等。不能把风险描述扩大为正常路径重复计数或永久损坏，也无须立即迁移数据库。
- R2 的恢复日志只保存已验证的差量批次，使用既有私有原子文件机制和 128 MiB 大小上限。超出上限会在数据族发布前返回错误。它保护本地组合观察的查询与恢复，不承诺所有历史文件的独立读取都属于同一个数据库事务。
- `paste` 是维护警告；`lru` 的公告不能单独证明本应用存在可利用漏洞。选择移除受影响版本，未添加公告忽略规则。
- 平台配置、交叉编译和原生运行是不同证据。本次 macOS 原生测试通过，Windows 做了 MSVC 全测试目标类型检查；尚无本次 Windows 原生 ConPTY 执行或控制台关闭事件的实测结果。
- 未对真实用户服务执行安装、切换或卸载；服务超时和协调锁行为通过隔离进程及临时状态目录验证。也未声称完成真实 SSH 端到端同步或整机断电测试。

## 验证方式

使用仓库固定 Rust 1.97.0 和 locked 依赖。构建产物使用临时目录，不改动用户历史。
最终完整 macOS `cargo test --locked --all-targets`：1,746 个测试通过，1 个忽略。
唯一忽略的测试为仓库原有的真实用户历史性能基准，不属于正常回归套件。
最终 `cargo clippy --locked --all-targets -- -D warnings`、
`cargo fmt --all -- --check`、Windows MSVC `cargo check --locked --tests`
均通过；安装器测试和公开 TUI 预览一致性检查也通过。
`cargo audit --deny warnings` 为零漏洞、零公告警告。

R2 另有 25 项针对性测试及 3 项 TUI 缓存测试，覆盖六个持久化边界、
恢复中再次失败、空/partial 新输入、reconcile tombstone 重放、损坏/超限日志
拒绝、脱敏和私有权限，以及恢复后立即清除旧查询缓存。
